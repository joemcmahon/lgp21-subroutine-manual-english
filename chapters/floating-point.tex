\section{Floating-Point Interpretive Systems}
\label{sec:floating_point_interpreters}

\subsection*{FLOATING POINT INTERPRETER 1 --- H1-11.0}
\addcontentsline{toc}{subsection}{FLOATING POINT INTERPRETER 1 --- H1-11.0}
\label{H1-11.0}
\label{subsec:floating_point_1}

\subsubsection*{PURPOSE}
Floating-Point Interpretive System 1 is a 33-instruction interpreter that lets you write floating-point code on the LGP-21 without managing scale factors by hand. Inputs and outputs are 7-digit decimal mantissas with a separate power-of-10 exponent; the interpreter handles the binary mantissa/exponent split internally.

Each number is packed into one machine word in memory. While the interpreter is operating on a number it unpacks it into two words --- one for the mantissa, one for the exponent --- so the hardware can do ordinary signed arithmetic on each half. The exact bit layout is given under ``Internal Number Format'' below.

The interpreter is bundled with transcendental subroutines (data input/output, sin/cos, arctan, log, exp, sqrt) that are called as interpreter instructions, not as \texttt{B}/\texttt{R}/\texttt{U} calls --- once you're inside the interpreter loop, those operations are part of the instruction set. The interpreter engine itself and the companion fixed-point/floating-point conversion routine (\texttt{I3-12.0}) are entered with a normal machine calling sequence.

\subsubsection*{INTERNAL NUMBER FORMAT}
Each floating-point number is packed into a single word. The word holds two independent signed numbers: a mantissa $M$ and an exponent $E$, representing the value
\[ Z = M \cdot 2^E \]
The mantissa is a sign bit followed by 24 bits of magnitude, treated as a fraction at $q=0$. Mantissas are always stored normalized, so the leading magnitude bit has the place value $2^{-1}$. The exponent is a sign bit followed by 5 bits of magnitude, treated as an integer at $q=30$. Negative values in either field are stored in two's complement of the magnitude bits, with the two fields complemented independently --- so a negative mantissa and a positive exponent can sit in the same word without interfering.

That accounts for 31 of the LGP-21's 32 bits per word; the remaining bit is unused.

\paragraph{Translator's note: transcription errors in the worked examples}
The three worked examples below are transcribed from the original manual, but the bit patterns don't round-trip to the stated decimal values under the field layout described above. The $+3.75$ pattern has \texttt{011111} at the top of the word, which gives a 24-bit mantissa magnitude of 0.96875 rather than 0.9375. The $+0.46875$ pattern has the same problem. The $-3.75$ pattern's mantissa bits don't reconstruct $0.9375$ under either one's or two's complement.

The 24-bit mantissa width is independently confirmed by the Data Input section below, so the field layout above is right. The bit patterns themselves appear to be transcription errors in the original: each one has one too many \texttt{1} bits in the mantissa magnitude. I've left them as the original presented them rather than guess at what was meant; if you have hardware (or a verified reference manual) to test against, please file a PR.

\medskip
When a value is loaded into the floating-point accumulator or the multiplication register, it expands to two words --- one for the mantissa, one for the exponent --- with the mantissa shifted right by one bit (the ``implicit shift'' mentioned in the translator's note above; it puts the leading magnitude bit at $2^{-2}$ instead of $2^{-1}$). The mantissa and exponent are still paired as one logical value.

\subsubsection*{INTERNAL REGISTERS}
The interpreter provides four registers: a floating-point accumulator, a multiplication register, an address register, and an instruction counter. The accumulator and multiplication register each occupy two words (mantissa + exponent); the address and instruction-counter registers occupy one word each.

All four registers are zero when the program is first loaded. Apart from the instruction counter (which is reset on every entry into the interpreter and incremented per instruction), the registers persist across exits and re-entries: you can leave the interpreter, run native code, and come back without losing register state.

\paragraph{1. Floating-Point Accumulator.} Holds intermediate calculation results. Mantissa at $q=0$ (shifted right by one bit as described above), exponent at $q=30$, each with its own sign. Modified by arithmetic operations, function evaluations, and the Clear, Swap, and Set Sign instructions.

\paragraph{2. Multiplication Register ($M$-register).} Holds the multiplicand for the Multiply and Cumulative Multiplication instructions. Same internal layout as the accumulator. Modified only by the Set and Swap instructions.

\paragraph{3. Address Register.} A single word holding a track/sector value at $q=29$. Used by the Store Address instruction to patch the operand field of an instruction in memory, and by the Test for Zero branch. Modified only by Set Address and Increment Address.

\paragraph{4. Instruction Counter.} Holds the address of the currently-executing interpreter instruction, and points at the next instruction to fetch. Initialized by the main program's calling sequence on entry, and incremented by one per instruction. Jump instructions overwrite it with a new target; the Return instruction stores its current value plus 2 into the operand field of its target location.

\subsubsection*{FLOATING-POINT INSTRUCTIONS}
The interpreter has 33 pseudo-instructions. Each is a single word with an opcode and an operand address. In the descriptions below, \texttt{ttss} is an operand address in decimal track/sector format; instructions with operand \texttt{0000} have a special meaning (typically a register-only operation or a function call). All instructions run to completion without leaving the interpreter.
\begin{enumerate}
	\item Arithmetic Instructions
\begin{description}[leftmargin=1.5em, itemsep=4pt]
    \item[\texttt{B ttss} (Bring):] Load \texttt{ttss} into the accumulator.
    \item[\texttt{A ttss} (Add):] Add \texttt{ttss} to the accumulator.
    \item[\texttt{S ttss} (Subtract):] Subtract \texttt{ttss} from the accumulator.
    \item[\texttt{D ttss} (Divide):] Divide the accumulator by \texttt{ttss}.
    \item[\texttt{P ttss} (Set M-Register):] Load \texttt{ttss} into the $M$-register.
    \item[\texttt{M ttss} (Multiply):] Multiply the $M$-register by \texttt{ttss}; the product replaces the accumulator. $M$-register is unchanged.
    \item[\texttt{N ttss} (Cumulative Multiplication):] Multiply the $M$-register by \texttt{ttss} and add the product to the accumulator. $M$-register is unchanged.
    \item[\texttt{D 000y} (Shift Right):] Divide the accumulator by $2^y$ ($0 \le y \le 9$).
    \item[\texttt{M 000y} (Shift Left):] Multiply the accumulator by $2^y$ ($0 \le y \le 9$).
    \item[\texttt{H ttss} (Hold):] Store the accumulator into \texttt{ttss}. Accumulator is unchanged.
    \item[\texttt{C ttss} (Clear):] Store the accumulator into \texttt{ttss}, then zero the accumulator.
\end{description}

\item Jump / Branch Instructions
\begin{description}[leftmargin=1.5em, itemsep=4pt]
    \item[\texttt{U ttss} (Unconditional Jump):] Jump to \texttt{ttss}. Can't exit the interpreter --- \texttt{ttss} must point at another interpreter instruction.
    \item[\texttt{T ttss} (Test for Minus):] Jump to \texttt{ttss} if the accumulator is negative; otherwise fall through. Same restriction.
    \item[\texttt{800T ttss} (Conditional Jump):] Jump to \texttt{ttss} if the accumulator is negative \emph{or} if Program Selector Switch 7 (\texttt{PST}) is ON. Same restriction.
\end{description}

\item Address Modification Instructions
\begin{description}[leftmargin=1.5em, itemsep=4pt]
    \item[\texttt{E ttss} (Set Address):] Load the address field of the word at \texttt{ttss} into the address register.
    \item[\texttt{I ttss} (Increment Address):] Add \texttt{ttss} to the address register. Subtraction works by supplying the two's complement.
    \item[\texttt{Y ttss} (Store Address):] Write the address register into the address field of the word at \texttt{ttss} (other fields of \texttt{ttss} and the address register itself are unchanged).
    \item[\texttt{Z ttss} (Test for Zero):] If \texttt{ttss} equals the address register, skip the next instruction; otherwise fall through.
    \item[\texttt{R ttss} (Return):] Write (instruction counter + 2) into the address field of the word at \texttt{ttss}.
\end{description}

\item Auxiliary Instructions

The operand address field for all auxiliary commands must be exactly zero (\texttt{0000}).
\begin{description}[leftmargin=1.5em, itemsep=4pt]
    \item[\texttt{U 0000} (Swap):] Swap the $M$-register and the accumulator.
    \item[\texttt{B 0000} (Set Plus Sign):] Make the accumulator positive ($|x|$). No-op if already non-negative.
    \item[\texttt{T 0000} (Set Minus Sign):] Make the accumulator negative ($-|x|$). No-op if already negative.
    \item[\texttt{Y 0000} (Invert Sign):] Negate the accumulator.
    \item[\texttt{Z 0000} (Stop):] Halt execution. Pressing \textit{Start} resumes at the next instruction. Skipped if Break Point Switch 16 (\texttt{PS-16}) is ON.
    \item[\texttt{E 0000} (Exit):] Leave the interpreter. The next word is executed as a native machine instruction.
\end{description}

\item Input / Output Instructions

The operand address field for all I/O commands must be exactly zero (\texttt{0000}).
\begin{description}[leftmargin=1.5em, itemsep=4pt]
    \item[\texttt{I 0000} (Input):] Read a block of decimal numbers from tape, convert to floating-point, and store them in sequential locations. The destination address is taken from the tape's leader.
    \item[\texttt{P 0000} (Output):] Print the accumulator on the output device in floating-point notation. Accumulator is unchanged.
\end{description}

\item Transcendental Function Evaluation Instructions

The operand address field for all function evaluations must be exactly zero (\texttt{0000}).
\begin{description}[leftmargin=1.5em, itemsep=4pt]
    \item[\texttt{R 0000} (Square Root):] Replace the accumulator with $\sqrt{x}$.
    \item[\texttt{S 0000} (Sine):] Replace the accumulator with $\sin x$ ($x$ in radians).
    \item[\texttt{C 0000} (Cosine):] Replace the accumulator with $\cos x$ ($x$ in radians).
    \item[\texttt{A 0000} (Arctangent):] Replace the accumulator with the principal value of $\arctan x$ (result in radians).
    \item[\texttt{N 0000} (Natural Logarithm):] Replace the accumulator with $\ln x$.
    \item[\texttt{H 0000} (Exponential Function):] Replace the accumulator with $e^x$.
\end{description}
\end{enumerate}

\subsubsection*{Data Input and Output 1}
\label{subsec:data_io_1}

\subsubsection*{Data Input}
Data Input and Output 1 reads decimal numbers from tape, converts them to floating-point, and stores them in the locations you specify. It's invoked from inside the interpreter loop with an \texttt{I 0000} pseudo-instruction, and returns control to the instruction following the \texttt{I 0000} once all data has been read.

The input tape is structured as follows.
\begin{enumerate}[label=\alph*)]
\item \textbf{Input Keyword (Control Word).}
Each group of data starts with a control word: a signed two-digit decimal place count $P$ ($-03 \le P \le +16$) and the destination's starting address \texttt{ttss} in decimal track/sector notation. A positive $P$ shifts the decimal point left when the value is converted; a negative $P$ shifts it right.

\item \textbf{Numeric Data Elements.}
Each value is a signed decimal integer of up to 7 digits. Positive values may omit the plus sign and leading zeros; negative values must include all leading zeros between the minus sign and the first significant digit. A value of zero is just a single stop code (\texttt{'}).

\medskip
\textbf{Example:} with the control word \texttt{+032400'}, the value \textbf{16.192} is punched as \texttt{16192'}.\footnote{\textbf{Translator's Note:} Because $P = +03$, the interpreter shifts the implied decimal point 3 places to the left upon ingestion, reconstructing $16192 \times 10^{-3} = 16.192$.}

\item \textbf{End-of-Block Marker.}
A minus-zero word (\texttt{-0000000'}) marks the end of a group; it's not stored in memory, just consumed. The interpreter then expects another control word and starts a new group.

A minus-zero word followed by a second stop code (\texttt{-0000000''}) marks the end of the entire input. The subroutine prints a carriage return and returns to the interpreted program (the instruction following the \texttt{I 0000} that called it).

\subsection*{FIXED-POINT TO FLOATING-POINT CONVERSION (AND VICE VERSA) --- L3-12.0}
\addcontentsline{toc}{subsection}{FIXED-POINT TO FLOATING-POINT CONVERSION (AND VICE VERSA) --- L3-12.0}

\texttt{L3-12.0} converts a number between fixed-point and the floating-point format used by Floating-Point Interpreter System 1, in either direction. It's a standalone fixed-point subroutine, not part of the interpreter itself, intended for moving data in or out of the interpreter's world.

Exit the interpreter before calling. Place the number in the hardware accumulator and pass the scale factor $q$ in the calling sequence. The result comes back in the accumulator --- floating-point if you converted forward, fixed-point at the given $q$ if you converted back. One number per call.

Range limits: converting forward, the fixed-point number must not need an exponent greater than 31; converting back, the floating-point value must fit at the requested $q$.

\subsubsection*{OPERATION}

\paragraph{1. Program Input}
The system ships on two tapes: a relocatable hexadecimal tape compatible with Program Input 1 (\texttt{J1-10.0}), and a relocatable decimal coding-sheet tape. Both contain the interpreter core followed by the subroutines in the order shown under Memory Allocation. Program Input 1 is assumed to start at address \texttt{0000}.

On the hex tape, with \textsf{PS-32} \textsf{ON} the computer reads continuously up to the Fixed-Point/Floating-Point Conversion routine. With \textsf{PS-32} \textsf{OFF} it stops after each subroutine. There's no built-in stop between the interpreter core and Data Input and Output 1.

The decimal tape has built-in stops after the core and after each subroutine, regardless of \textsf{PS-32}.

The fixed/floating conversion routine must be loaded with a new modifier and a fresh device-selection keyword --- never the same modifier as any other part of the system.

On any stop, press \textsf{Start}: with \textsf{PS-32} \textsf{OFF} you return to Program Input 1 for the next entry; with \textsf{PS-32} \textsf{ON} the computer halts on the next input command inside Program Input 1.

\subsubsection*{REMARKS}

The initial location of the interpreter system should ideally align with Sector \texttt{00} of a track so that the reference addresses targeting Track 63 are optimally mapped.

Remember that when the interpreter is running all instructions are pseudo-instructions! The interpreter is substituting itself for the standard fetch-execute cycle that the CPU would do. Another way of saying it is that the interpreter is an emulator for a CPU that has a floating-point instruction set, and we have an agreed-upon protocol to enter and exit emulation.

Pseudo-instructions whose operand addresses are between \texttt{0000} and \texttt{0009} have special meanings: rather than referring to those memory locations, they invoke interpreter functions (transcendentals, register operations, etc.). The interpreter has 16 such address-driven operations. The shift instructions \texttt{D 000y} and \texttt{M 000y} use \texttt{y} (1--9) as a shift count, not as a memory address, which means standard \texttt{D ttss} or \texttt{M ttss} instructions inside the interpreter cannot reference locations \texttt{0000}--\texttt{0009}.

\subsubsection*{EXAMPLE}

This example evaluates a fourth-degree polynomial $y = A_4 x^4 + A_3 x^3 + A_2 x^2 + A_1 x + A_0$ using Horner's method:
\[ y = ((((A_4) x + A_3) x + A_2) x + A_1) x + A_0 \]

Rather than unrolling the additions and multiplications, the program uses the interpreter's address-modification instructions (\texttt{E}, \texttt{I}, \texttt{Y}, \texttt{Z}) to step through the coefficients in a loop, patching the add-instruction's operand on each iteration to point at the next coefficient.

The interpreter core is loaded at \texttt{0300}. The program loads at \texttt{4200}; \texttt{X}-prefixed instructions are not relocated, others get \texttt{4200} added to their operand by the loader. Lines \texttt{00} and \texttt{01} are native code that enter the interpreter; from line \texttt{02} on, everything is an interpreter pseudo-instruction (until \texttt{XE} at \texttt{12} exits back to native, where \texttt{13} halts the machine in fixed-point mode).

\subsubsection*{INTRODUCTION}

Floating-Point Interpretive System 2 is a 33-instruction floating-point interpreter (like H1-11.0) but with much wider range and higher precision, at the cost of using two memory words per number instead of one. Inputs are 9-digit signed decimal mantissas with a 2-digit decimal exponent ($\pm 99$); outputs are 7-digit decimal mantissas with the same exponent range.

The interpreter ships on a single tape (relocatable hex, compatible with Program Input 1, \texttt{J1-10.0}) bundling Data Input, Data Output, and the usual transcendental functions. Only the subroutines you actually need must be loaded, but the cross-reference addresses between subroutines must be preserved when you do.

If your data swings across many orders of magnitude, this interpreter saves a lot of the scaling bookkeeping you'd have to do by hand in fixed-point.

\paragraph{Principles}
The interpreter presents the LGP-21 to the programmer as if it had a native floating-point instruction set. To do this it provides:

\begin{enumerate}
    \item \textbf{Software registers}: a floating-point accumulator, a multiplier register, an address register, and an instruction counter.
    \item \textbf{A richer instruction set}: arithmetic and transcendentals (including a multiply-accumulate), sign manipulation, address-register operations, and built-in I/O.
    \item \textbf{Wide numerical range}: inputs are signed 9-digit mantissas with a base-10 exponent in $\pm 99$; outputs are signed 7-digit mantissas with the same exponent range.
    \item \textbf{Built-in I/O}: dedicated read and print pseudo-instructions for floating-point data.
\end{enumerate}

The complete system takes 28 tracks of memory: the interpreter core plus Data Input (7 tracks), Data Output (4 tracks), and floating-point functions (6 tracks). That leaves 36 tracks (2,304 words) for the main program and data.

\subsubsection*{INTERNAL REGISTERS}

The interpreter provides four registers: a floating-point accumulator, a multiplier register, an address register, and an instruction counter. The accumulator and multiplier register are each two words wide (matching the in-memory two-word floating-point format); the address register and instruction counter are each one word.

All four registers are zero on initial load. Instructions referenced in the descriptions below are detailed in the Pseudo-Instructions section.

\paragraph{1. Floating-Point Accumulator.} Holds intermediate calculation results and output values. Mantissa at $q=0$, 30 bits of precision, normalized so the leading bit is at $2^{-1}$; exponent at $q=29$; each with its own sign bit. Modified by arithmetic, transcendental functions, and the Clear, Swap, and Set Sign instructions.

\paragraph{2. Multiplier Register.} Holds the multiplicand for Multiply and Cumulative Multiplication. Same internal layout as the accumulator. Modified only by Set and Swap.

\paragraph{3. Address Register.} A single word holding a track/sector address at $q=29$. Used by Store Address to patch the operand field of an instruction, and by the zero-test branch. Modified only by Set Address and Increment Address.

\paragraph{4. Counter Register.} The interpreter's program counter. Holds the address of the current pseudo-instruction and points at the next. Initialized by the main program's calling sequence on entry, and incremented by one per instruction. A Return instruction stores (counter + 2) into the operand field of its target. Jumps and conditional branches overwrite it.

\subsubsection*{INTERNAL NUMBER FORMAT}

Each floating-point number occupies two consecutive locations:
\begin{itemize}
    \item \textbf{First location}: the mantissa $M$ at $q=0$ --- a sign bit plus 30 magnitude bits, always stored normalized (so the leading magnitude bit has the place value $2^{-1}$).
    \item \textbf{Second location}: the exponent $E$ at $q=29$ --- a sign bit plus magnitude bits, a small integer.
\end{itemize}

The represented value is $Z = M \cdot 2^E$.

\subsubsection*{INPUT}

The pseudo-input instruction (\texttt{I0000}) requires a data paper tape formatted precisely as follows:
\begin{enumerate}
    \item A starting address block.
    \item The raw data formatted as signed decimal integers coupled with their respective exponents.
    \item A designated group-termination code at the end of each distinct cluster of numbers.
    \item A final master execution stop-code at the terminal end of the data tape.
\end{enumerate}

\paragraph{The Starting Address}
Every independent data group must begin with its target starting memory location, designated in decimal Track/Sector notation. This must be an absolute address and must be immediately followed by a physical stop-code (\texttt{'}). 

\textit{Example:} The entry \texttt{4200'} instructs the input subroutine to begin storing the incoming converted floating-point variables sequentially starting at location \texttt{4200}.

\paragraph{The Data Structure}
Following the starting address line, one or more signed decimal integers and their exponents are fed into the reader. The subroutine converts this decimal matrix into internal binary floating-point representations and stores them in consecutive, two-location blocks on the drum.

Each individual floating-point value must be explicitly split into \emph{two distinct words} on the paper tape, each line capped with a hardware stop-code (\texttt{'}). 
\begin{itemize}
    \item \textbf{Negative values:} The minus sign (\texttt{-}) must immediately precede the very first digit of the first word.
    \item \textbf{Positive values:} A space may be inserted before the first digit, but a physical plus sign (\texttt{+}) is strictly prohibited.
\end{itemize}

The structural payload layout across the tape lines is split as follows:
\begin{itemize}
    \item \textbf{Word 1:} Contains the algebraic sign bit and the first seven digits of the decimal integer.
    \item \textbf{Word 2:} Contains the final two digits of the decimal integer, followed immediately by the sign and the two digits of the base-10 exponent.
\end{itemize}

Formally, the physical tape notation maps to this exact structural syntax:
\begin{center}
\ttfamily
\begin{tabular}{ll}
\textnormal{\textbf{Line 1 (Word 1):}} & $\pm d_1d_2d_3d_4d_5d_6d_7'$ \\
\textnormal{\textbf{Line 2 (Word 2):}} & $d_8d_9\pm e_1e_2'$ \\
\end{tabular}
\end{center}
Where $\pm d_1d_2d_3d_4d_5d_6d_7d_8d_9$ constitutes the total 9-digit signed decimal integer, and $\pm e_1e_2$ represents the 2-digit decimal scaling exponent.

\medskip
The mathematical value of the processed data variable is determined by the underlying relationship:
\[ \text{Represented Value} = \text{Integer} \times 10^{E_{10}} \]
Where the exponent boundaries are hardcoded at: $-99 \le E_{10} \le +99$.

\paragraph{Input Encoding Examples}
\begin{itemize}
    \item \textbf{Example 1:} Consider the fraction $0.0900000521374209$. This corresponds mathematically to the scientific notation expression: $521374209 \times 10^{-16}$. To feed this value into the interpreter, it must be punched onto the paper tape as two distinct lines:
    \begin{verbatim}
    5213742'
    09-16'
    \end{verbatim}
    
    \item \textbf{Example 2:} Consider the large whole number $5522829640000000$. This corresponds to the mathematical notation: $552282964 \times 10^{+07}$. It must be presented to the reader as:
    \begin{verbatim}
    5522829'
    64+07'
    \end{verbatim}
\end{itemize}

\paragraph{Termination Stopcodes}
The system defines two distinct classes of termination stop-codes. Their behavior varies fundamentally based on their context and placement on the data coding sheet:
\begin{enumerate}
    \item \textbf{Group Termination Code:} Signifies the end of the current numerical data block. It commands the system to immediately begin reading the next subsequent address and data group on the tape.
    \item \textbf{Master Input Stop-Code:} Signifies the total completion of data entry. It triggers an automatic terminal carriage return, shuts down the tape reader pipeline, and gracefully jumps execution control back to the next sequential line of the user's main program.
\end{enumerate}

\subsubsection*{OUTPUT}
The output format works to make the numbers a consistent size on the page, and to have a consistent format. Each number has:
\begin{itemize}
	\item a leading character for the sign. This will be a space for positive numbers, and $-$ for negative ones,
	\item the mantissa of the floating-point number, in leading-decimal format,
	\item a separator space,
	\item the sign of the exponent (this is either $+$ or $-$, and \emph{always} appears),
	\item the two-digit exponent itself, and
	\item a tab character.
\end{itemize}

The \texttt{space}/$-$ convention means that positive and negative numbers will align properly to the left down a column.

The tab character enables the user to easily create well-formatted output on the Flexowriter by setting the hardware tab stops.

Control is immediately returned to the main program loop after printing is complete. A single floating-point number is processed and output per subroutine invocation. The actual printed format of a number looks like this:

\begin{center}
\small
\begin{tabular}{rl}
% Row 1: The printed text format string (with explicit leading space)
Positive&\texttt{\phantom{-}.xxxxxxx\ $\pm$ee[Tab]} \\
Negative&\texttt{-.xxxxxxx\ $\pm$ee[Tab]} \\
\end{tabular}
\end{center}

\medskip
This physical teleprinter serialization format represents the standard mathematical expression:
\begin{equation*}
\pm\text{.\texttt{xxxxxxx}} \cdot 10^{\pm\text{\texttt{ee}}}
\end{equation*}

\paragraph{Output Limits and Constraints}
The formatting routine enforces the following mathematical boundaries during execution:
\begin{itemize}
	\item \textbf{Decimal Exponent Range:} $-99 \le ee \le +99$.
	\item \textbf{Decimal Mantissa Bounds:} $0.1000000 \le \lvert\text{mantissa}\rvert \le 0.9999999$, or exactly zero.
	\item \textbf{Internal Binary Exponent Range:} $-333 \le \text{exponent} \le +333$.
\end{itemize}

An underflow condition occurs when where the internal binary exponent drops below $-333$; this causes the routine to automatically print a clean zero. Conversely, an overflow condition where the binary exponent exceeds $+333$ triggers a terminal range error stop, halting the interpreter loop.

\paragraph{Running the interpreter}
Entry to the interpreter is via a subroutine call using an \texttt{R}/\texttt{U} sequence. Similar to the Floating-point Interpreter I,
the \texttt{R} instruction sets the address portion of a \texttt{B} instruction at $L_0$, which in this case acts as an executable pointer back
to the pseudo-instructions inline after the \texttt{U}. The interpreter extracts the address of the code to be interpreted from this \texttt{B}
instruction. It does \emph{not} set a return address, but instead uses the \texttt{E0000} instruction to detect the end of the interpreted
pseudo-instructions, and branches back to the (fixed-point) instruction following the end of the floating-point code.

\paragraph{Precision and Accuracy}
\begin{itemize}
	\item \textbf{Sine-Cosine:} Maximum error is $5 \times 10^{-8}$.
	\item \textbf{Data Output:} The maximum error is limited to:
	\begin{itemize}
		\item $1$ unit in the last decimal place of the mantissa if $\text{EXP}_{10} \le 30$.
		\item $5$ units in the last decimal place of the mantissa if $\text{EXP}_{10} \le 99$.
	\end{itemize}
\end{itemize}

\textbf{Translator's note:} To print a floating-point number, the data output routine has to convert a binary exponent ($2^x$) into a decimal exponent ($10^y$). Mathematically, this requires multiplying or dividing the mantissa by powers of 10 (or powers of $\log_{10}(2)$) until the binary scaling is cleared out.
\begin{enumerate}
	\item For $\le 30$: For these exponents, the conversion can be done using exact or very tightly bounded multiplication factors that fit cleanly within a single or double-word of 31-bit precision. The rounding error is kept to a minimum of 1 unit in the last place.
	\item For $> 30$: For very large numbers (up to $10^{99}$), the output routine has to repeatedly multiply by large powers of 10. Because of the LGP-21's 31-bit word size, the intermediate multiplication constants themselves have to be rounded to fit. As the algorithm repeatedly loops and multiplies to scale down large exponents, the rounding errors in these constants also multiply.
\end{enumerate}

By the time the conversion routine finishes working through a number like $10^{95}$, the accumulated rounding error corrupts the bottom bits of the mantissa, producing an output that could be off by up to 5 units in the 7th decimal digit.

\subsubsection*{REMARKS}

\begin{enumerate}
\item A program can exit H1-11.1 interpreter mode and return to it without the contents of the pseudo-registers being lost.
\item The starting address of the system should be at sector 00 of a track. Otherwise, many of the addresses that refer to track 63 are not optimal.
\item It's good practice to load the entirety of \texttt{H1-11.1}, and to then punch out the individual sub-libraries by means of \texttt{J4-10.2} or \texttt{J4-10.3}. This enables you to load only the parts that you require using \texttt{J1-10.0} or by means of \texttt{J5-10.0}. This allows you to verify checksums on load.
\item Instructions with zero addresses do not actually refer to location 0000, but are used to indicate special pseudo-instructions. The interpreter has 14 pseudo-instructions with zero addresses, plus the two special shift instructions \texttt{D000y} and \texttt{M000y}. These instructions set their address part to values from 0001 to 0009, meaning that the division and normal multiplication instructions must not use these addresses in interpreter mode.
\end{enumerate}

\subsubsection*{Translator's Notes}

\paragraph{Why do we have \emph{two} floating point packages?}
Modern programmers would look at this documentation and immediately start trying to figure out how to get rid of one of these two packages. Why would anyone want, or need, two separate floating point packages?

The following is speculation, based off the architectures of the two interpreters and years of experience with human nature, so take it with a grain of salt. If we ever have a real LGP-21 programmer around to ask, who actually \emph{used} both, we can nail it down for sure. But having said that, it appears that there two different floating-point interpreters because there were two different audiences who needed floating point.

The first set of users would be people who are familiar with the LGP-21 and the fixed-point frctional architecture; who are comfortable thinking about numbers in terms of $q$ and who have relatively lightweight requirements for floating-point operations. They will be writing code mostly in LGP-21 native mode, and occasionally dropping into floating point for a few calculations. Basic I/O of floating point works fine for them. Interpreter 1 is their choice.

The second set of users are primarily engineers, mathematicians, scientists...anyone whose native way of thinking about math is ``things you do with real numbers''. They want an instruction set that natively Does The Thing, using floating point numbers. Power-of-10 scaling makes perfect sense to them, but bit-twiddling and screwing around with representation is a distraction from the work they need to get done. Their attitude is effectively: \emph{``I just want to work with actual numbers. These fixed-point fractions are too weird.''}

There are tradeoffs; we can see some of them from the descriptions of the two interpreters:
\begin{itemize} 
	\item Interpreter 2 has a pad word following each mantissa-exponent pair, interpreter 1 doesn't. Is this because the all-float interpreter 2 runs \emph{slower} than the limited interpreter 1? Or is it a brilliant speed hack that makes it run \emph{faster}? 
	\item Code written for interpreter 1 is \emph{probably} faster, up to a point, but after the ratio of fixed-point to floating-point operations tilts far enough toward floating-point, the overhead to move in and out of floating-point mode and the overhead to move \emph{data} in and out will eventually make the interpreter 1 program larger than the same program written for interpreter 2, which doesn't have the mode-switch overhead, and eventually \emph{may} make it slower.
	\item An Interpreter 2 program may be slower than an Interpreter 1 program, but it is likely to be \emph{smaller} because the mode-switch overhead is no longer needed.
\end{itemize}

We won't know for sure until we find a programmer who used both, or two programmers who have had a 50-plus year argument about which is better.

\paragraph{Why interpreters?}
A modern programmer's second thought is ``why are the LGP-21's floating point implementations \emph{interpreters?}'' Couldn't we just write some nice libraries and call it a day?

On a more modern machine with a stack or other good support for subroutine calls, sure. (We'll pretend it doesn't have native floating point.) Let's say we're doing \texttt{fmul(fadd(a,b),fadd(c+d))}. We'd put a on the stack, call the conversion routine, push b on the stack, convert it, call the float-add function, put c on, convert, put d on, convert, call float-add, call float-multiply, done!

On the LGP-21, there are \emph{so many} more operations. We have no stack, so everything has to go in temporary storage. We can't hold a two-word (mantissa and exponent) number in the regular accumulator, so we'll have to do something like this\footnote{This is only the instructions needed to set up to \emph{do} the operations; we're skipping the actual functions and the wiring necessary to do things like set up return addresses, find arguments, etc. Those are assumed to be library overhead and not something the caller codes...but that overhead exists too.}:

	\textbf{Operation} & \textbf{Estimated} & \textbf{Description} \\

\paragraph{Coding example for Interpreter 2}
This is a far better example of using all of the facilities of Interpreter 2 than the very simple comparison program above.

The Interpreter 2 Horner's Method example shows how a program would have been coded on an LGP-21 coding sheet, and then fed to one of the program loaders in \ref{sec:program-loaders} to make it resident in memory.

The program as designed is set up to allow the user to run the program, enter a set of exactly 5 coefficients (we're not up to handling dynamic loops here), and have them multiplied out:
$$f(x) = a_4x^4 + a_3x^3 + a_2x^2 + a_1x + a_0$$
\paragraph{Reading an LGP-21 coding sheet}
We've elected to keep the coding sheet for this particular example instead of writing out assembler code because it's useful to see how an LGP-21 program was coded by hand.
Note that the locations start at 00 and go up; these line numbers act as ``virtual'' memory addresses, and can be referred to by other instructions by number, very much like a BASIC program. Instead of a \texttt{GOTO 200}, you have a \texttt{U 0015} to branch to the instruction on line 15.

The instructions with a leading \texttt{x} are \emph{non-relocated}; their addresses are not modified when the program is loaded. For example, lines 0 and 1 set up Interpreter 2 by saving the address of the instruction 2 on from line 0 into the interpreter itself, at the fixed address 1400. Additionally, the interpreter's special \texttt{I} and \texttt{P} instructions, to read and write data, have to have an address field of exactly 0000 to work properly, so those instructions are also marked as non-relocatable.

These two items together are key to understanding how the program works. A more modern\footnote{Or at least as modern as you're going to get for a computer built in 1963} assembler would have had labels for the line-number branches that the coding sheet uses, but would still emit assembled code that looks more like the coding sheet than anything else.
\paragraph{How the Horner's Method coding sheet and data input sheet would have been used}
To actually execute this on the LGP-21, an operator would have gone through the following sequence:
\begin{enumerate}
	\item Power on the LGP-21 and ensure the Loader Utility Program is resident in memory. Load it if not.
	\item Sit down at the Flexowriter and type out the coding sheet to produce a physical paper tape punched with the instruction bits and carriage-return stop codes (').
	\item Take the finished source tape, walk over to the LGP-21 console, and feed it into the paper tape reader.
	\item Set the console switches to execute the resident loader, and sets the input device to the paper tape reader, then tells the loader to load the tape.
	\item The loader starts the tape and reads the initial tape headers (;0004200 and /0004200), targets Track 04 Sector 00, and begins shifting the relative instruction addresses to match their new home on the drum.
	\item Once the program tape finishes loading, the operator removes it and inserts a Data Tape containing the actual floating-point numbers for $x$ and the polynomial coefficients
	\item The operator clears the manual controls and presses \textsf{START} on the physical control panel.
	\item The computer starts executing the program, which starts Interpreter 2, pauses at Line 02 (xI 0000), readss in the data values from the data tape, and immediately begins crunching the numbers through the self-modifying loop.
	\item The interpreter finishes the math, commands the Flexowriter to type out the final evaluation result on paper (\texttt{xP 0000}), drops out of interpretive mode, and triggers a hard system stop via Line 13 (\texttt{xZ 0000}).
	\item If the operator wants to clear the current run and evaluate a completely fresh data tape using the same polynomial structure, they simply hit \textsf{START} again. The machine executes Line 14 (\textsf{U 0000}), which immediately vectors execution right back to the beginning of the program loop (relative line 0) to read the next input tape of $x$ and the coefficients. 
\end{enumerate}
